# Contributing

Thank you for looking. This project is small and opinionated, and the fastest
way to get a change merged is to know which half of the repository it belongs in.

## The one rule

**`canon/` is written by hand. Almost everything else is generated.**

```
canon/palette/*/palette.yml   ← edit this
        │
        ▼  python3 tools/build.py
library/themes/**             ← never edit these
library/web/palette.css
library/integrations/**
canon/palette/*.css · *.json · CONTRAST.md
docs/assets/**  ·  docs/banner.svg  ·  package.json
```

If you find yourself editing a file with `generated by tools/build.py` in its
header, stop: the change belongs upstream, and CI will reject the file anyway.

The one hand-written artifact outside `canon/` is
[`library/web/yoshiki.css`](library/web/yoshiki.css) — the component kit. Edit
it there; the build mirrors it into `docs/` so the showcase always wears the
file the repository ships.

## Before you open a pull request

```bash
python3 tools/build.py          # regenerate
python3 tools/build.py --check  # must print "clean"
python3 tools/check.py          # must print "clean"
```

Both run in CI. The first fails if committed output no longer matches canon, or
if any role drops below its contrast floor. The second fails on a hard-coded
colour in the showcase, a dead link, a stale copy of a token value, or a
Japanese character.

If you touched the site, also run the optional sweep — it needs a browser, so it
is not in CI:

```bash
npm i playwright-core && node tools/audit.mjs   # must report nothing
```

## Changing a colour

Expect this to be harder than it looks, and expect the build to argue with you.
Every text role is measured against every surface it can sit on, in both themes,
and one cell below its floor fails the build. That is deliberate: it has already
caught six real failures that reading could not.

When the proof rejects a value, the fix is almost always a few RGB points, not a
new hue. [The forge](https://zinzaki.github.io/yoshiki/palette.html#forge) is the
fastest way to find out what a change does before you commit it.

## Adding a theme target

One `emit` block in `tools/build.py`, next to the others. Every target resolves
from the same tokens, so you are describing the shape of that program's config
file — not choosing colours again. Add the file pair to
`library/themes/README.md` and the target list in `README.md`.

## Style

- **Follow the language.** The repository is written in the thing it documents:
  restrained, exact, no ornament that earns nothing. Comments explain *why*, not
  *what*.
- **Prose is English.** The language takes ideas from Japanese aesthetics and
  attributes them in `PHILOSOPHY.md`; it does not scatter characters as
  decoration, and the build enforces that.
- **Reach for a role, never a raw token.** In the kit, in the site, in an
  example. A raw token carries no contrast promise, and that promise is the whole
  point of the roles layer.

## Reporting something

Open an issue. If it is a contrast or accessibility problem, include the two
role names and the theme — that is enough to reproduce it exactly.
