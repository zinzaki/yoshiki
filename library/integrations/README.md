Every file here is generated by `tools/build.py`. An integration that drifts
from the palette is worse than no integration, so none of them are edited by
hand — change `canon/palette/*/palette.yml` and rebuild.

| file | for |
|---|---|
| [`tailwind.cjs`](tailwind.cjs) | a Tailwind preset — `y-*` role classes, `yt-*` raw tokens |
| [`tokens.mjs`](tokens.mjs) · [`tokens.d.ts`](tokens.d.ts) | a typed module, for anything that imports rather than links |
| [`figma-variables.json`](figma-variables.json) | one collection, two modes — Figma variables and Tokens Studio |
| [`style-dictionary.config.json`](style-dictionary.config.json) | Style Dictionary v4, pointed at the DTCG files |

## npm

```bash
npm i yoshiki-design
```

```js
import 'yoshiki-design/css';                     // tokens + roles, both themes
import 'yoshiki-design/kit.css';                 // the component kit
import { kogane, washi } from 'yoshiki-design';  // resolved values, typed
```

```html
<html data-theme="washi">   <!-- light; omit for the dark default -->
```

## Tailwind

```js
// tailwind.config.js
module.exports = { presets: [require('yoshiki-design/tailwind')] };
```

```html
<button class="bg-y-bg-raised text-y-action-text border border-y-action-edge rounded-control">
  Publish
</button>
```

The preset's colours resolve to the **role variables**, not to baked hexes, so
one preset covers both themes and a token change reaches your utilities without
a rebuild. Load `yoshiki-design/css` alongside it — that is where the variables
come from. Raw tokens are available under the `yt-` namespace when you genuinely
need a fixed value; reach for a role first.

## Figma

`figma-variables.json` is one collection with two modes, which is the shape
Figma variables and Tokens Studio both want. Import it, bind a layer to
`text-body` rather than to `bone-1`, and switching the mode switches the file.

## Style Dictionary

The config consumes the W3C DTCG files the build already writes, so you are not
translating a translation:

```bash
npx style-dictionary build --config library/integrations/style-dictionary.config.json
```

Out of the box that produces CSS variables, an ES module, a Swift class and
Android colour resources. Add platforms as you need them — the source of truth
does not change.

## Which one should you use

Reach for CSS variables if you can: they follow the theme by themselves, and
they are the only form where a role stays a role. The typed module resolves to
fixed values, which is right for a canvas, a chart library or a native target,
and wrong for anything that can switch theme at runtime.
