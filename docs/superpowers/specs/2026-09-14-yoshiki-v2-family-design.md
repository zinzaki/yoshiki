# yoshiki v2 — язык, семейство палитр, темы

Статус: черновик на утверждение · 2026-09-14 · основание: 13 раундов визуального голосования.

## 1. Суть

yoshiki — **язык оформления**: правила, объекты и паттерны, которые годятся везде. Цвет в нём —
отдельный сменный слой. Порядок производства:

```
язык (правила · роли · компоненты · паттерны)      ← ядро, от палитры не зависит
   └─ семейство палитр (12)                        ← цвета + роли, ничего кроме цвета
        └─ темы (производные)                       ← палитра, применённая к поверхности
             └─ примеры и паттерны                  ← готовые страницы, меню, карточки
```

- **Палитра** — именованные цвета и роли (фон, текст, постоянный акцент, сигнал, синтаксис).
  Никаких шрифтов, углов, орнаментов.
- **Тема** — палитра на конкретной поверхности: kitty, VS Code, nvim, web-кит (чистый / с орнаментом),
  карточка Telegram. Одна палитра → много тем. Орнамент, скругления, шрифты — это настройки темы.
- **Зона применения** обязательна для каждого правила и компонента (раздел 4).

## 2. Роли (общие для всех палитр)

| роль | смысл |
|---|---|
| `bg.app` · `bg.surface` · `bg.raised` · `bg.hover` | глубина поверхностей |
| `border.hairline` · `border.strong` | разделители |
| `text.primary` · `text.secondary` · `text.muted` · `text.ghost` | иерархия текста |
| `bar.fill` · `bar.text` | тёмная плашка заголовка (грамматика NieR) |
| `accent.edge` · `accent.text` · `accent.onBar` | **постоянный акцент**: знак, рамка, выбранное, курсор |
| `signal.fill` · `signal.text` · `signal.onFill` | **редкий сигнал**: ошибка, удаление, блокировка |
| `glow` | цвет свечения для графических тем (может быть = сигнал или акцент) |
| `syntax.keyword/function/string/number/type/comment` | код; по умолчанию «тёплый яркий, исправленный» |
| `term.*` | ANSI-16 для терминала (терминал — тёмный остров во всех светлых палитрах) |

Контраст проверяется на каждой поверхности (как сейчас в `build.py`): текст ≥ 4.5:1, ghost и кромки ≥ 3:1.

## 4. Зоны применения

| зона | где | чем рисуем |
|---|---|---|
| **текст** | терминал, TUI, CLI-вывод, чаты и боты, комментарии в коде, README | символьные рамки, глифы, текстовые спиннеры, ANSI; в Telegram — картинка-карточка или моно-карточка |
| **графика** | десктоп-приложения, веб | настоящие компоненты web-кита, иконки (набор, упакованный в приложение), графические анимации, стекло, паттерны |

Правило для агентов: сначала определить зону, потом брать компоненты. Символьные рамки в графической зоне
запрещены; компоненты web-кита в текстовой зоне невозможны.

## 5. Структура репозитория

```
canon/
  language/            principles · roles.md (контракт ролей) · zones.md
  text/                lexicon (frames, glyphs, nameplates, space, states) · motion (text) · cli · messaging · comments
  graphic/             components · effects · motion (graphic) · icons · typography
  palettes/
    <slug>/palette.yml ← 12 палитр, только цвет и роли
    CONTRAST.md        ← доказательство для всех палитр
  prompts/             модули; identity без привязки к палитре + palette-модуль на каждую палитру
library/
  themes/<app>/<slug>.*   ← генерируются для каждой палитры (13 программ × 12)
  web/                    ← кит: clean и ornate — варианты темы, палитра подключается отдельно
  text/ · menus/ · charts/ · frames/ · loaders/   ← текстовая зона (frames/loaders возвращаются из recover/pr3)
  telegram/               ← генератор карточки-картинки + моно-шаблоны
  examples/               ← примеры страниц и паттернов
tools/build.py            ← цикл по всем палитрам; проверки контраста на каждой
AGENTS.md                 ← маршрут: зона → язык → палитра → тема
```

## 6. Порядок работ

1. Данные: 12 `palette.yml` по новой схеме ролей; архивировать kogane/washi.
2. `build.py`: цикл по палитрам, генерация тем для всех программ, контраст для всех, `--check` в CI.
3. Канон: разнести lexicon/components по зонам; `roles.md`, `zones.md`; обновить AGENTS.md и prompts.
4. Web-кит: палитра через CSS-переменные ролей; темы clean / ornate (крестики, уголки, подсказки) и радиусы.
5. Вернуть из `recover/pr3` frames, loaders, charts, text, если они проходят новые правила зон.
6. Telegram: генератор PNG-карточки в цветах палитры.
7. README и сайт — отдельной спецификацией после шагов 1–4.

## 7. Проверка

`python3 tools/build.py --check` и `tools/check.py` зелёные; контраст всех ролей на всех поверхностях для
12 палитр; скриншоты сайта-витрины палитр (1440 и 390) через headless Chromium из кэша Playwright.
