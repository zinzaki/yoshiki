# yoshiki v2 — фундамент: ресурсы, язык, материалы, палитры, объекты, галерея, сайт

Статус: черновик на утверждение · 2026-09-15.
Основание: 13 раундов голосования, спецификация семейства палитр (2026-09-14), аудит репозитория,
исследование профессиональных систем (DTCG 2025.10, Material 3, Fluent 2, Radix, shadcn registry,
tinted-theming, Slint).

## 1. Что такое yoshiki

yoshiki — **фундамент визуального мира**: его ресурсы, материалы, физика и правила. Всё остальное
строится из него: интерфейсы проектов (exet-os, приложения на Slint, веб), темы программ, промпты для
нейросетей, сайт.

Порядок работ: **сначала весь фундамент грубо, потом каждую часть доводим голосованием**, как палитры.

Вне ядра:
- `yoshiki-themes` — отдельный репозиторий с темами программ (kitty, VS Code, nvim…), собирается из
  токенов yoshiki по модели tinted-theming;
- сами проекты пользователя, которые подключают токены и берут объекты.

## 2. Слои

```
L0  ресурсы      референсы → разбор → извлечённые компоненты (с ID)
L1  язык         принципы, зоны, контракт ролей, правила для агентов
L2  материалы    стекло, бумага, лак, зерно, свечение · свет, глубина, движение («физика»)
L3  палитры      семейство: имена, коды, классы; каждая заполняет один и тот же набор ролей
L4  объекты      компоненты по зонам: графика (web, desktop) и текст (терминал, TUI, чат)
L5  паттерны     композиции объектов: экраны, блоки, сцены
L6  галерея      записи «превью + промпт + команда», разложенные по полкам
──  выходы       CSS · DTCG · Tailwind · Figma · Slint · текстовые (Lip Gloss, Textual, Ratatui) · registry
```

Правило зависимостей: слой ссылается только на слои ниже себя. Палитра не знает об объектах,
объект берёт роли, а не значения, паттерн собирается из объектов по ID.

## 3. Идентификаторы

У каждой сущности есть постоянный ключ. Ключи не переиспользуются, при переименовании остаётся
старый ключ со ссылкой на новый.

```
yk:<вид>/<путь>

yk:ref/0042                     референс из мастерской
yk:mat/glass.frost              материал
yk:fx/glow.warm                 эффект
yk:mo/enter.rise                движение
yk:pal/night-beige              палитра (плюс короткий код, формат выбирается голосованием)
yk:role/accent.edge             роль
yk:obj/graphic/button.primary   объект графической зоны
yk:obj/text/frame.capsule       объект текстовой зоны
yk:pat/graphic/installer.disk   паттерн
yk:tr/ornate                    вариант оформления (clean, ornate…)
yk:ty/geist                     шрифтовая пара
```

Для чего нужны ключи:
- генератор собирает промпт из выбранных ключей;
- поиск и точная выборка;
- ссылки между слоями, например у паттерна поле «derived-from: yk:ref/0042»;
- ссылки из промптов: нейросеть получает ключ и находит описание.

## 4. Манифест записи

Любая сущность описана одним YAML-манифестом рядом со своими файлами:

```yaml
id: yk:pat/graphic/installer.disk
kind: pattern                  # ref | material | effect | motion | palette | object | pattern | treatment | type
title: Disk partition editor
zone: graphic                  # graphic | text | any
surfaces: [desktop, web]       # desktop | web | mobile | terminal | tui | chat | comment
shelf: [installer, forms]      # таксономия полок галереи
tags: [nier, glass, dense]
uses: [yk:obj/graphic/segmented-bar, yk:mat/glass.frost, yk:role/accent.edge]
derived-from: [yk:ref/0042]
palettes: any                  # any | [yk:pal/...]
treatments: [clean, ornate]
status: draft                  # draft | voted | stable | deprecated
preview:
  format: pattern.screens      # формат из каталога превью (§5)
  files: [preview/1440-dark.png, preview/1440-light.png, preview/390-dark.png]
prompt: prompt.md              # промпт, который воспроизводит запись
command: yoshiki add yk:pat/graphic/installer.disk
votes: {round: 2026-09-20, verdict: want}
```

Манифесты проверяются JSON Schema в CI. Сборка генерирует из них индекс для сайта, генератора и
агентов (`registry.json`, совместимый со shadcn).

## 5. Превью по видам

Превью подобрано под вид записи, а не случайный макет:

| вид | формат превью |
|---|---|
| палитра | карточка-образец в форматах Pinterest (пользователь пришлёт примеры), полоса ролей, живая сцена |
| материал | плитка материала на светлом и тёмном фоне, с запасным вариантом без прозрачности |
| эффект, движение | короткое видео или живая демонстрация, кадр-постер |
| объект графики | лист состояний: обычное, наведение, фокус, нажатие, отключено, ошибка, загрузка |
| объект текста | рендер терминала с точной сеткой и ANSI |
| паттерн | экраны 1440 и 390 в двух темах |
| референс | исходник (приватно) и разбор с выделенными фрагментами |

Превью снимает Playwright в CI. Тот же прогон служит визуальной регрессией.

## 6. Мастерская: приём референсов

1. Пользователь кладёт фото, ссылки и источники в `workshop/inbox/`. Папка не коммитится: картинки
   чужие и личные.
2. Разбор каждого референса «по винтикам»: материал, цвет, типографика, сетка, приёмы UI, эффекты,
   движение, настроение и почему это может нравиться. Выводы не строятся на частоте повторов,
   рассуждения глубокие, выводы подаются как гипотезы.
3. Результат — `workshop/refs/<id>/analysis.md` в репо (текст и собственные схемы, без чужих картинок)
   и черновые записи L2–L5 со ссылкой `derived-from`.
4. Черновики проходят раунд голосования, после этого получают статус `voted`.

## 7. Язык (L1)

- `canon/language/zones.md` — графика и текст, таблица «можно и нельзя», маршрут для агентов.
- `canon/language/roles.md` — единый набор ролей, который заполняет каждая палитра:
  - поверхности: `bg.app/surface/raised/hover`;
  - линии: `border.hairline/strong`;
  - текст: `text.primary/secondary/muted/ghost`;
  - плашка: `bar.fill/text`;
  - акцент: `accent.edge/text/onBar`;
  - сигнал: `signal.fill/text/onFill`;
  - `glow`, `syntax.*`, `term.*`.

  Старые имена ролей (`action.*`, `danger.*`) остаются псевдонимами на одну мажорную версию.
- `canon/language/principles.md` — принципы v2 вместо текстов v1 про лак, кость и золотой шов.
- `AGENTS.md` — короткие правила «всегда / спросить / никогда», наверху команды; остальное подгружается
  по запросу.

## 8. Материалы и физика (L2)

- Материал — составной токен: `blur, tint, tintOpacity, noise, border, borderOpacity, glow, glowSpread`
  и обязательный `fallback`. Fallback включается при `prefers-reduced-transparency`,
  `prefers-contrast: more` и на слабом железе.
- Стартовый набор:
  - `glass.frost` — матовое стекло;
  - `glass.clear` — прозрачное стекло;
  - `paper` — бумага;
  - `lacquer` — лак;
  - `grain` — зерно;
  - `glow.warm` — тёплое свечение;
  - `pattern.cross` — сетка крестиков;
  - `pattern.dots` — точечная матрица;
  - `hud.lines` — линии HUD;
  - `seal` — красная печать.

  Стартовый набор взят из голосований.
- Физика:
  - `elevation` — лестница поверхностей: тон и стекло, тень только у плавающих слоёв;
  - `motion` — длительности, кривые, сценарии входа и выхода, таблица замен для reduced motion;
  - `light` — откуда свет, как ведёт себя свечение;
  - `density` — плотность;
  - `radius` — скругления (6 / 10 / 14 / пилюля);
  - `space` — отступы;
  - `layout` — сетка и брейкпоинты.
- Только графическая зона. Текстовая зона получает свои примитивы: рамки, глифы, спиннеры,
  таблицы деградации ANSI.

## 9. Палитры (L3)

- Семейство из 14 палитр: 12 из кастинга, плюс Lab и Hanko без золота.
- Устройство семейства, формат кода и имена решаются голосованием (раунд опубликован).
- Каждая палитра хранится в `canon/palettes/<slug>/palette.yml` и описывается метаданными:
  - `name`, `slug`, `code`;
  - `mode`, `pair`;
  - `temperature`, `accent`, `material`.
- Значения в OKLCH, контраст по WCAG 2.2 — жёсткая проверка, APCA — информационно.
  Декоративный порог для рамок объявляется в самой палитре, как у Beige glass.

## 10. Объекты и паттерны (L4–L5)

- Графическая зона:
  - базовые объекты: кнопки, поля, выбор, переключатели, списки, таблицы, меню, диалоги, уведомления,
    вкладки, навигация, окно;
  - грамматика NieR: плашка, квадратный маркер, выбранная строка в рамке;
  - варианты `clean` и `ornate`;
  - реализации: CSS-кит и Slint-компоненты.
- Текстовая зона:
  - базовые объекты: рамки, промпт, статусы, деревья, таблицы, спиннеры, прогресс, меню, сообщения
    бота и карточки Telegram;
  - возвращаются из `recover/pr3` с новыми токенами.
- Первые паттерны — под реальные проекты: установщик и настройки exet-os, файловый менеджер и пульт
  на Slint, веб-консоль, лендинг, документация.

## 11. Сайт

- **Хаб.** Главная с первым впечатлением уровня Active Theory и Lusion: WebGL-сцена из материалов
  yoshiki. Дальше показ живых кусков фундамента. Палитру и стиль главной можно переключать и
  комбинировать.
- **Палитры.** Каждая в лучшей реализации: адаптированная сцена, образцы, коды, скачивание токенов.
- **Галерея.** Полки, фильтры по зоне, поверхности, палитре и оформлению; живое превью; кнопка
  «копировать промпт» и команда.
- **Генератор.** Выбор блоков, материалов, палитры и оформления по ID; на выходе готовый промпт и
  список ключей.
- **Мастерская.** Разборы референсов.
- **Документация.** Язык, роли, зоны.
- Техника:
  - статический сайт на GitHub Pages;
  - данные из сборки;
  - WebGL на небольшой библиотеке (OGL или three.js) с запасным вариантом без WebGL;
  - всё уважает reduced motion.

## 12. Структура репозитория

```
AGENTS.md  llms.txt  README.md  CHANGELOG.md
canon/
  language/     principles.md · zones.md · roles.md
  materials/    <id>/manifest.yml + spec.md
  physics/      elevation.md · motion.md · light.md · density.md · radius.md · space.md · layout.md
  palettes/     <slug>/palette.yml · archive/ · CONTRAST.md
  objects/      graphic/<id>/ · text/<id>/
  patterns/     graphic/<id>/ · text/<id>/
  treatments/   clean · ornate
  type/         шрифтовые пары
  prompts/      модули промптов, собираются из манифестов
workshop/       refs/<id>/analysis.md  (inbox/ не коммитится)
library/        готовые реализации: web/ · slint/ · text/ (frames, loaders, menus, charts) · telegram/
schema/         JSON Schema манифестов и палитр
tools/          build.py (resolve → emit → registry) · check.py · previews (Playwright)
site/           исходники сайта; сборка кладёт в docs/
```

Темы программ, конфиги и пресеты уходят в `yoshiki-themes`.

## 13. Сборка и проверка

Порядок в CI:
1. проверка схем;
2. сборка токенов и выходов;
3. индекс `registry.json`;
4. контраст (WCAG — жёстко, APCA — справочно);
5. `check.py`: зоны, ID, ссылки, CJK;
6. Playwright: превью и регрессия;
7. публикация сайта.

Версии по semver: переименование ключа — мажорная, новая запись — минорная, правка значения — патч
с обязательным визуальным просмотром.

## 14. Этапы

1. **Каркас.** Структура, схемы манифестов, ID, `zones.md`, `roles.md` с псевдонимами, перенос canon
   по новым папкам, вынос тем в `yoshiki-themes`.
2. **Палитры.** Итоги раунда имён; 14 палитр как данные; выходы для всех.
3. **Материалы и физика.** Грубо весь стартовый набор с превью.
4. **Объекты.** Графика (CSS и Slint) и текст (возврат pr3), состояния, превью.
5. **Паттерны и галерея.** Паттерны под exet-os, Slint и веб; индекс, промпты, команды.
6. **Сайт.** Хаб, палитры, галерея, генератор.
7. **Доводка.** Раунды голосования по каждой части; дальше мастерская пополняет базу.

## 15. Решения (2026-09-15)

- Спецификация утверждена, начинаем с этапа 1.
- Картинки-референсы хранятся только локально (`workshop/inbox/` в `.gitignore`); в репо попадают
  разборы и извлечённые компоненты.
- Сайт: Vite и WebGL-библиотека (three.js или OGL), статическая сборка на GitHub Pages.
- Установка записей: реестр, совместимый со shadcn (`npx shadcn add …`); своя CLI не нужна.

Открыто: форматы превью палитр из Pinterest — ждём примеры от пользователя.
