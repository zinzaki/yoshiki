Thirteen targets, one source.

Every file below is baked out of a single palette by tools/build.py, and CI re-runs the build to make sure the committed output still matches. Nothing here is maintained by hand — change one token in canon/palette and all thirteen move together. The previews are drawn from the same values the files carry.

01 the terminal

A dark island, in both themes.

The terminal never inverts. Even under washi, where the page is paper, the terminal stays lacquer — so the two theme files of a terminal-drawn target carry the same values, and the ANSI ramp is shared. Blue, wisteria and celadon exist only here and in syntax; they never enter the UI.

02 the editor

Syntax lives in the roles, too.

An editor follows the theme it is in — paper under washi, lacquer under kogane — while its integrated terminal stays the dark island. Keywords take the gold, strings the moss, numbers the persimmon; types and constants are the one place the cool service hues are allowed. Each is measured against the page it renders on.

03 everything else

Prompt, panes, pickers, gauges.

The parts of a desk that usually end up mismatched. Each one is generated from the same tokens, so the seam between them disappears.

04 add your own

One emit block is a new target.

Every target resolves from the same tokens, so adding an app means writing how its file is shaped — not choosing colours again. That is the whole argument for generating them: a palette change reaches thirteen programs at once, and a fourteenth costs an afternoon.
