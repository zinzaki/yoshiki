canon palette

Tokens, roles, and the proof.

Two layers. Tokens are the raw paint — ink-0, kin-1 — and they carry no promise. Roles are the contract: reach for text.body or action.edge and the right value arrives in either theme, at a contrast that has been measured against every surface it can land on. Everything on this page is read from the same file the build reads. Click any value to copy it.

◆ the contract

Roles — what you actually consume.

A role resolves to a token, and a theme may remap it. That is the whole mechanism behind the classic trap: gold is readable as an edge but not as a word, so the language splits it into border.gold and text.gold — and on paper only the second one sinks. You cannot pick wrong if you reach for the role.

◆ proven, not asserted

Every role, on every surface it can sit on.

Measuring text against one flattering background is how a palette hides its failures. This matrix is generated by the build and the build fails on a single cell below its floor — including bg.hover, which on paper is the darkest ground of all.

◆ the forge

Move the source. Watch everything follow.

Two claims run through this repository: that one file decides everything downstream, and that the contrast is proven rather than asserted. Both are easy to write and hard to believe — so take the source apart and watch. The page recolours, the generated files rewrite themselves, and the entire WCAG matrix re-runs on every frame. Push far enough and the proof starts failing, which is exactly what it is for.

The transform runs in OKLab, not HSL. HSL's "lightness" is not lightness — rotating hue in it swings perceived brightness wildly, which would make the contrast readout a lie.
